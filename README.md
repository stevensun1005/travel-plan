你有一份旧PDF、几张机票截图、一串想去的地方，还有「别太赶」「吃好一点」「预算别爆」这些真实需求。

**travel-plan** 是给 Claude 和 Codex 使用的旅行规划 skill。它把这些资料整理成一份能看地图、切换机酒方案、实时算预算、发给同伴的网页。交付包含可编辑数据、网页和校验工具，不只是一段聊天记录。

## 先看看成品

### 真实案例：多伦多直飞欧胡岛，一月五晚

**这是用 travel-plan 做的一份真实攻略，两个人、一辆只租一天的车、一个不爬山也能玩遍的欧胡岛。**

Air Canada 直飞和 Expedia 机酒套餐二选一（选套餐时酒店和接送自动切成「已含」，预算饼图按单订价拆分套餐）、五家酒店的 Vio 含税价、古兰尼牧场深度团、恐龙湾跟团浮潜、观光巴士上钻石山、日落帆船看天气放 1/4 或 1/7、两种护照的入境证件和要提前抢的预订都在待办清单里。

不用配置 API key 或安装前端依赖，就能体验机酒选项、预算占比和记账式明细（每个分类点「+」展开每一笔；租车和交通这类相关的类别在饼图里合成一块，点开再分）、要带多少现金（美元 / 当地货币各多少、用在哪）、航班切换、真实路线地图（缩小能看到世界地图，一键「和多伦多一起看」出发地和目的地的位置关系）、一键分享并保存路线图和出发前待办清单。手机上也专门排过版：两行顶栏、左右滑的日期和景点卡片。界面是方格纸上的手绘图解风，右上角可切到黑板主题，左上角有一只背着相机的旅行小羊驼。顶栏的「做同款攻略」（页面底部也有「复制提示词」）会复制一段话，粘贴给 Claude Code 或 Codex 就能安装 travel-plan、做一份自己的攻略。

## 这份 skill 会多做哪一步

| 你会说的话 | travel-plan 会落实成什么 |
| --- | --- |
| 「我还有一份旧攻略，都加进去」 | 逐项提取、去重与覆盖表，交代安排、替代、备选和取消 |
| 「回来转两次机也行，想省钱」 | 对应日期与人数的全程报价，比较舱等、转机、到家日和行李 |
| 「想租双座敞篷，我还不到25」 | 按年龄、门店、车型、实际租期查资格与完整总价，不猜青年费 |
| 「她能正常走，只是不hiking」 | 保留正常参观与上下车，把山顶步道改成明确的外围体验 |
| 「地图别再画个大概」 | 经纬度、真实底图、缓存道路线、每日筛选、分段里程和导航 |
| 「酒店机票让我自己选」 | 可选方案、自定义金额、预算上限、总额/余额与支出占比联动 |
| 「跨年有什么特别的」 | 核对本年度活动、节日关闭、晚秀与游船冲突，区分常规节目 |
| 「怎么发给同伴」 | 白名单静态打包；按授权部署并交付确认成功的分享链接 |
| 「我订的是机酒套餐」 | 选中套餐时酒店（和接送）自动切成「已含在套餐」，取消后恢复，总价不重复计算 |
| 「地图太空了」「发布后地图不显示」 | 自带OpenStreetMap离线底图：陆地、山区、湖泊、公路分级（含三级公路）、编号牌、地名，图块被拦截也能看；范围盖住常看的画面，不会一圈都是「海」 |
| 「缩小了想看它在世界哪里、离家多远」 | 页面自带世界国家轮廓和中文国名（Natural Earth），缩小到哪都有底图；写上出发地（`map.home`）就会标出来，并多一个「和多伦多一起看」按钮，一键把出发地和目的地放进同一画面 |
| 「两家酒店分开选，但饼图里想看成一块」 | 左边各类照样分开选，右边饼图按 `chartGroups` 合成一块（如「酒店」「租车与油费」），点开再列出每一项 |
| 「要换多少美元和当地钱」 | 预算下面一块「换钱」：美元和当地货币各带多少、在哪换（出发前换还是落地ATM取）、面额怎么配，每笔现金用途（只收现金的门票、小费、小摊、停车）列清楚 |
| 「想发一张路线图给朋友」 | 地图旁「分享路线图」按钮，生成手绘海报：每天路线、景点贴纸和每日亮点 |
| 「我们俩护照不一样，其中一个是永久居民」 | 按每人护照、居留身份和已有签证查入境/回程要求（如EVUS、PR卡），和要预订的项目一起写进带截止日与倒计时的待办清单 |
| 「机票酒店帮我找最便宜的」 | 先问要不要直飞、对航空公司有没有要求；再在航司官网、Trip.com/携程、Booking.com、Expedia、Vio 分别查同一个产品，外币按加拿大央行汇率换成加币，选最便宜的并在选项后写上平台；机票一律按每人含1件随身行李箱比较 |
| 「钱具体花在哪几笔」 | 预算饼图下每个分类一行，点「+」像记账软件一样展开每一笔：项目、金额、占这一类的比例 |
| 「手机上看着别扭」 | 手机版两行顶栏（导航不再挤成竖排），日期筛选和景点变成左右滑的卡片，点卡片地图自动定位；分段路程默认收起 |
| 「做得好看一点」 | 方格纸 / 黑板两套手绘图解风主题，手写体标题、荧光笔重点、登机牌航班卡 |

**也支持把多城旅行做成选择器。** 用户需要时，Agent会扩展底板：自由勾选城市、改晚数和顺序、切换火车/飞机，联动日期、住宿、路线和预算；围绕球赛等必参加事件排程。景点详情就近展开照片、推荐理由、停留时间及门票，所有备选线路使用同样标准。指定Expedia时按对应行程核价，改条件会使不匹配报价失效，并保留手填预算。详见 [多城市工作流](references/multi-city.md)；欧胡岛演示用的是单城市基础底板。

## 三步安装

网页底板不需要 npm install，也不需要 API key；本地工具需要 **Python 3.10+**，Node.js 18+ 仅用于开发校验和 JS 测试。

### 在 Claude 里用（自动更新）

上传 [`claude-skill/travel-plan`](claude-skill/travel-plan/SKILL.md) 这个文件夹（打成 zip，里面是 `travel-plan/SKILL.md`）到 Claude 的 skills 设置里。它很短，只做一件事：每次启动先把这个仓库克隆或 `git pull` 到工作区的 `.skills/travel-plan`，再照仓库里的完整 `SKILL.md` 做。所以只要上传一次，以后仓库更新会自动生效；拉取失败时继续用已有版本，不会丢本地改动。

### 在 Codex 里用

```bash
git clone https://github.com/stevensun1005/travel-plan.git
cd travel-plan
python scripts/install.py
```

默认安装到 `$CODEX_HOME/skills/travel-plan`，未设置时为 `~/.codex/skills/travel-plan`。安装器遇到同名目录会保留原文件并停止；可用 `--destination` 指定另一位置。安装后在 Codex 中用 **`$travel-plan`** 调用。

## 复制一句话开始

**从零规划**

```text
用 $travel-plan 做一份两人海边旅行攻略：
从我的出发城市出发，五晚，含机票酒店活动的总预算有上限。
想吃海鲜、看海、浮潜，考虑敞篷车，不安排hiking。
把酒店、机票和租车做成可选项，总预算和占比图随选择更新。
先沿用已经告诉你的信息，只问真正缺少的事项。
```

**合并旧资料**

```text
用 $travel-plan 把附件PDF里的所有想去地点合并到现有攻略。
晚数不变，取消我已经说不做的项目；排不下、改成替代或视排队的要说明。
重新核对开放日、路线、预约和预算，并更新真实地图。
```

**查实际报价**

```text
用 $travel-plan 查指定日期、两位成人的机票和全住期酒店总价。
租车按我实际年龄、驾照和租期看含税保障总价。
给不同预算选项，标明查价日期、退款、行李、停车及尚未核实的费用。
```

**分享给同伴**

```text
用 $travel-plan 把已经完成的攻略发布成有链接即可查看的网页。
保留互动预算和地图，返回确认成功的线上链接。
不要把原始资料、发布凭据和整个工作目录一起上传。
```

**多城自由组合**

```text
用 $travel-plan 做几版跨国路线，让我勾选城市、调整顺序和每城晚数。
优先火车，也保留飞机选项，围绕我必须参加的比赛排程。
按 Expedia 的对应日期完整票价比较性价比，变更条件后标明报价需重查。
各版景点都在展开日程里附照片、为什么值得去、停留时间和门票价格。
改选择后同步日期、住宿、交通、地图和预算，保留我手填的金额。
```

## 预算为什么不会悄悄翻倍

- 机票是一份完整往返总价，不把去程卡与回程卡各算一遍。
- 酒店按全住期计算；餐费、停车、强制费用的口径写清楚。
- 套餐已含的晚餐、门票和接送只计一次。
- 行李等有依赖的金额随所选航班调整。
- 机酒套餐用 `bundles` 声明包含哪些类别，被包含的类别自动锁定为「已含」，不会和单订酒店叠加。
- 用最小货币单位累计，自定义负数、损坏的保存内容和零预算都有处理。
- 饼图是**当前支出构成**；未用预算不混成一块“支出”。
- 分类明细（`items`）加起来必须等于选项金额，校验器会查；套餐拆分、行李联动时明细按比例折算，展开后的每一笔和饼图对得上。
- 饼图合并（`chartGroups`）只是把几类放在一块显示，金额照各自的选择相加，不改变总额。
- 「换钱」区块是带现金的建议，不是另一笔支出，不进饼图；里面的小费等如果没在别的类别里，要在机动额度里留出来。

## 常见问题

<details>
<summary>“实时预算”会自动抓机票和酒店的新价格吗？</summary>

不会。实时是指你选择方案或修改金额后立即重算。商家价格沿用明确注明日期的查价记录或估算，重新查价需要Agent访问可用的实时来源。

</details>

<details>
<summary>有PDF就能直接导入吗？</summary>

有可用的PDF提取能力时，skill会先转为文字/Markdown，必要时查看页面图像，再把地点逐项纳入。图片型PDF可能需要OCR；它不会把无法识别的内容假装已完整读到。

</details>

<details>
<summary>地图到底是真实的，还是装饰性的示意图？</summary>

使用Leaflet、OpenStreetMap和真实经纬度；道路线来自缓存OSRM结果。没有路由数据就先显示地点和导航，不画虚构曲线。游船、接驳、军事基地和观光巴士不会用汽车最短路冒充。

在线图块下面还有一层用OpenStreetMap数据生成的离线底图（`fetch_basemap.py`），发布到会拦截外部图片的托管环境时，地图依然有陆地、湖泊、公路和地名。分享海报也用同一份数据在浏览器里画出来。再往下是一份随页面打包的简化世界地图（Natural Earth 1:110m，公有领域），所以地图缩小到整个大陆也不会变成空白；国界是示意，不作权威边界。

</details>

<details>
<summary>发给同伴后，两人的预算选择会同步吗？</summary>

各自保存在各自的浏览器，不会互相覆盖，也不自动同步。`127.0.0.1`只能本机访问；要异地分享需要部署到可访问的托管服务。发布能力取决于当前环境的工具与授权。

</details>

<details>
<summary>它会直接订票、付款或帮我发消息吗？</summary>

不会把“制作攻略”理解成购买或代发权限。所有未预订的项目保留未预订状态，发布和付款也遵循各自实际授权。

</details>

<details>
<summary>我只有一个很小的修改，也要重跑全部流程吗？</summary>

不用。已有项目按当前请求定向修改，保留历史决定、清单和无关数据。只做适合本次变更的验证。

</details>
